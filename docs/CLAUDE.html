Reglas del proyecto

Normas de desarrollo del Gestor de Registros WinCC. Las siguen tanto las personas como el asistente de IA (Claude Code).

Versión HTML de CLAUDE.md. Ver también el README y la guía técnica y de uso.

Entorno
Python 3.12 en .venv. Ejecutar siempre con .venv\Scripts\python.exe.
Dependencias
Toda dependencia nueva se instala con scripts\agregar_dependencia.ps1 <paquete>, que la fija con su versión en requirements.txt y regenera requirements-lock.txt. Nunca pip install suelto.
Idioma y tiempo
Código y textos de la interfaz en español. Tiempos internos = epoch ms en hora local de planta (como WinCC).
Base de datos
La BD se elige solo por la URL de config/config.yaml. Usar únicamente tipos y consultas SQLAlchemy genéricos (nada específico de SQLite) para poder migrar a SQL Server o PostgreSQL.
Ingesta
La ingesta nunca debe perder ni duplicar datos: cualquier cambio en app/ingest.py debe mantener verdes tests/test_ingest.py, tests/test_operacion.py y tests/test_propiedades.py.
Pruebas
Antes de dar un cambio por terminado, .\scripts\probar.ps1 (o -Rapido) debe acabar en «TODO EN VERDE»: todas las pruebas pasan, sin avisos (pytest.ini los convierte en error) y cada módulo crítico (ingest, wincc_csv, reports, auth) con cobertura ≥ 90 %. Código nuevo ⇒ pruebas nuevas. Endpoint nuevo ⇒ declararlo en la matriz de tests/test_permisos_audit.py.
Audit trail
Todo cambio de configuración hecho por usuarios (límites, variables, usuarios) se registra con app.audit.record.
Documentación
La que leen las personas va en HTML autocontenido en docs/. Los .md (README.md, CLAUDE.md) se conservan como contexto para la IA; al cambiar uno, actualizar también su copia docs/README.html / docs/CLAUDE.html.
